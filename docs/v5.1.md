# Leo Personal Website - v5.1

## Task

Implement Version 5.1 of the personal website.

The goal of this version is to turn the existing Markdown blog index into a real readable blog system.

Version 5.0 already supports:

* Markdown files in `content/blog`
* Blog metadata loading
* Slug generation
* BlogCard components
* `/blog` article list

Version 5.1 should add:

* Blog detail pages
* Dynamic blog routes
* Markdown body rendering
* Navigation from BlogCard to article pages

Keep the implementation focused.

Do not add unrelated blog features in this version.

---

## Current Project Status

The project currently uses:

* Next.js App Router
* React
* TypeScript
* Tailwind CSS

Current version:

```text
5.0
```

Current routes:

```text
/
/projects
/blog
/about
```

Current blog files:

```text
content/blog/

├── personal-website-codex.md
├── ctf-learning.md
├── cs231n-learning.md
└── machine-learning-andrew-ng.md
```

Version 5.0 already reads metadata from these files and displays them on `/blog`.

However, visitors currently cannot open or read the Markdown article body.

---

# Main Goal

Create this complete blog flow:

```text
/blog
  ↓
BlogCard
  ↓
/blog/[slug]
  ↓
Load Markdown file
  ↓
Render article metadata
  ↓
Render Markdown body
```

Example:

```text
/blog/cs231n-learning
```

should render the content from:

```text
content/blog/cs231n-learning.md
```

---

# Requirements

## 1. Add Dynamic Blog Route

Create:

```text
app/blog/[slug]/page.tsx
```

Use the Next.js App Router dynamic route system.

The `slug` should correspond to the Markdown filename.

Examples:

```text
personal-website-codex.md
→ /blog/personal-website-codex

ctf-learning.md
→ /blog/ctf-learning

cs231n-learning.md
→ /blog/cs231n-learning

machine-learning-andrew-ng.md
→ /blog/machine-learning-andrew-ng
```

---

## 2. Extend Blog Data Loader

Update:

```text
lib/blog.ts
```

The existing loader already reads blog metadata.

Extend it so that it can also retrieve a single complete blog post by slug.

The returned article data should include:

```text
slug
title
description
date
category
content
```

where:

```text
content
```

contains the Markdown body after the frontmatter.

Keep blog file-reading logic inside `lib/blog.ts`.

Do not place filesystem logic directly inside React page components.

---

## 3. Preserve Existing Metadata Logic

Do not unnecessarily rewrite the existing Version 5.0 blog system.

Reuse the current:

* metadata validation
* slug generation
* sorting behavior

when possible.

Only extend the architecture where necessary.

The existing simple frontmatter format is sufficient for Version 5.1.

Do not build a full YAML metadata system unless it becomes technically necessary for this task.

---

## 4. Render Markdown Article Content

Add Markdown body rendering.

The article page should convert Markdown such as:

```markdown
# Introduction

This is my learning note.

## What I Learned

- Topic A
- Topic B

**Important concept**
```

into properly styled HTML content.

Use a simple and maintainable Markdown rendering approach.

If an additional Markdown dependency is necessary, use a small, well-maintained package.

Do not introduce a large blog framework.

---

## 5. Article Page Layout

Each article page should display:

```text
Category

Article Title

Description

Publication Date

----------------

Markdown Article Content
```

Example:

```text
Computer Vision

CS231n Learning Notes

Notes and experiments while learning Stanford CS231n.

August 21, 2026


Introduction

...

Image Classification

...
```

Keep the design consistent with the existing site.

---

## 6. Article Reading Width

The article body should be optimized for reading.

Requirements:

* Do not stretch text across the entire desktop screen.
* Keep a comfortable article width.
* Preserve readable line lengths.
* Keep typography consistent.
* Maintain sufficient spacing between headings and paragraphs.

The article page must remain responsive.

---

## 7. Style Basic Markdown Elements

Support clean styling for at least:

* `h1`
* `h2`
* `h3`
* paragraphs
* unordered lists
* ordered lists
* bold text
* italic text
* links
* inline code
* code blocks
* blockquotes

Do not implement advanced syntax highlighting yet.

Code blocks only need to be readable.

Full syntax highlighting belongs to Version 5.2.

---

## 8. Update BlogCard Navigation

Modify:

```text
components/BlogCard.tsx
```

Each BlogCard should allow the visitor to open the corresponding article.

Use Next.js:

```text
Link
```

Possible interaction:

```text
Read article →
```

or make the title/card area link to:

```text
/blog/[slug]
```

The interaction should be clear and accessible.

---

## 9. Handle Invalid Slugs

If a visitor accesses a blog slug that does not exist, such as:

```text
/blog/not-existing-post
```

use the appropriate Next.js App Router behavior.

Prefer:

```text
notFound()
```

Do not display a broken article page.

---

## 10. Static Generation

Because blog posts are stored locally as Markdown files, use static generation where appropriate.

If suitable, generate article routes from the known blog slugs.

Prefer a simple Next.js-native solution.

Do not introduce runtime server infrastructure unnecessarily.
