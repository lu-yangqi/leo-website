# Leo Personal Website - v6.2

## Task

Implement Version 6.2 of the personal website.

The goal of this version is to introduce a maintainable English / Chinese bilingual foundation for the core website.

Codex is primarily responsible for:

* Language-switch architecture
* English / Chinese switching UI
* Reusing existing components
* Loading the correct language content
* Preserving routes and functionality
* Maintaining SEO-friendly structure where practical

Codex should NOT independently rewrite, reinterpret, or creatively translate important personal-profile content.

The English and Chinese wording should come from confirmed bilingual content data.

---

# Core Principle

Use:

```text
Confirmed English Content
        +
Confirmed Chinese Content
        ↓
Shared Website Components
        ↓
Language Switch
```

Do NOT use:

```text
English Page
        ↓
Runtime Translation API
        ↓
Automatically Generated Chinese Page
```

There should be no runtime dependency on:

* Google Translate
* DeepL API
* AI translation API
* Browser automatic translation
* External translation services

The website should work completely without an external translation service.

---

# Translation Responsibility

Important personal content must have reviewed English and Chinese versions.

Examples:

```text
Bio
Research Interests
Technical Interests
Skills
Currently Learning
Education
Project descriptions
Navigation labels
CTA labels
```

Codex may reorganize this content into an appropriate data structure.

Codex should not substantially change its meaning.

If a Chinese translation is missing, do not invent major personal claims.

Prefer leaving the missing item clearly marked for later content completion rather than generating unsupported wording.

# Language Switch Behavior

When the user selects:

```text
EN
```

core website UI and content should display English.

When the user selects:

```text
中文
```

core website UI and content should display Chinese.

The selected language should remain consistent while navigating between core pages.

For example:

```text

→ About
→ Projects
```

should not unexpectedly switch language.

Use a simple, scalable architecture.

Prefer one of these approaches:

## Option A — Locale Routes

Example:

```text

/en/about
/en/projects

/zh
/zh/about
/zh/projects
```

or:

```text
/en/...
/zh/...
```

## Option B — Shared Route with Language State

Example:

```text
/about
/projects
```

with a persistent language selection.

Codex should inspect the current Next.js App Router structure and choose the cleaner solution.

Preference:

Use a Next.js-native architecture that is:

* Maintainable
* SEO-friendly
* Easy to understand
* Easy to extend later

Avoid unnecessary internationalization frameworks if native routing and data structures are sufficient.
