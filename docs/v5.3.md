# Leo Personal Website - v5.3

## Task

Implement Version 5.3 of the personal website.

The goal of this version is to upgrade the existing Markdown blog into a more complete technical knowledge system.

Version 5.2 should already provide:

* Markdown blog index
* Dynamic article routes
* Markdown body rendering
* Syntax highlighting
* Blog categories
* Blog tags
* Improved Markdown typography
* Article metadata
* Back to Blog navigation

Version 5.3 should focus on advanced blog navigation and content discovery.

Main features:

1. Table of Contents
2. Previous / Next article navigation
3. Blog search
4. Tag filtering
5. Category filtering
6. Reading time
7. Reading progress indicator
8. Improved article navigation

Do not rebuild the existing blog architecture unnecessarily.

Extend the existing system.

---

# Main Goal

Upgrade the current flow:

```text
Markdown Posts
      ↓
Blog Index
      ↓
Article Page
```

into:

```text
                    Blog
                     │
        ┌────────────┼────────────┐
        ↓            ↓            ↓
      Search      Categories     Tags
        │            │            │
        └────────────┼────────────┘
                     ↓
              Filtered Articles
                     ↓
                 BlogCard
                     ↓
              /blog/[slug]
                     │
        ┌────────────┼─────────────┐
        ↓            ↓             ↓
       TOC      Reading Time    Progress
        │
        ↓
     Article
        │
        ↓
 Previous ← Article → Next
```

The blog should begin to feel like a real technical knowledge base.

# Requirement 1 — Add Reading Time

Calculate estimated reading time for every article.

Do not manually write reading time inside Markdown metadata.

Calculate it automatically from article content.

A simple approach is sufficient.

For example:

```text
5 min read
```

or:

```text
8 min read
```

Use a reasonable reading-speed estimate.

Avoid unnecessary dependencies if this can be implemented simply.

---

## Display Reading Time

Display reading time on:

### BlogCard

Example:

```text
CS231n Learning Notes

Computer Vision

Aug 21, 2026 · 6 min read

CS231n · CNN · Computer Vision
```

### Article Header

Example:

```text
COMPUTER VISION

CS231n Learning Notes

Notes and experiments while learning Stanford CS231n.

Aug 21, 2026 · 6 min read

CS231n · CNN · Computer Vision
```

Keep it visually secondary.

# Requirement 2 — Add Table of Contents

Technical articles may become long.

Generate a Table of Contents automatically from Markdown headings.

Use:

```text
h2
h3
```

headings.

Avoid including the article title itself if the article page already displays it separately.

---

## Example

Markdown:

```markdown
## Image Classification

### KNN

## Neural Networks

### CNN

### ResNet
```

should generate approximately:

```text
On this page

Image Classification
    KNN

Neural Networks
    CNN
    ResNet
```

---

# Heading IDs

Rendered Markdown headings should have stable IDs.

Example:

```markdown
## Image Classification
```

should produce something similar to:

```text
#image-classification
```

Table of Contents links should navigate to these headings.

Do not manually hard-code article TOCs.

---

# TOC Layout

Desktop:

Prefer a readable layout such as:

```text
Article Content              On this page

Introduction                 Introduction
...                          Image Classification
                             CNN
                             ResNet
```

The Table of Contents may appear beside the article if the existing design supports it cleanly.

Do not make the main article text too narrow.

---

## Mobile TOC

At approximately:

```text
390px
```

do not force a permanent sidebar.

Use a simpler layout.

Possible solutions:

* TOC above the article
* Collapsible TOC
* Compact TOC section

Choose the simplest maintainable approach.

Avoid complex mobile navigation libraries.

---

# Requirement 3 — Previous / Next Article Navigation

At the bottom of each article, display navigation to adjacent posts.

Example:

```text
← Previous

Learning CTF and Cyber Security


Next →

CS231n Learning Notes
```

Use article date ordering consistent with the existing Blog index.

Do not maintain previous / next links manually inside Markdown.

Generate them from the existing blog data.

---

## Edge Cases

For the first article:

```text
Previous
```

may not exist.

For the last article:

```text
Next
```

may not exist.

Do not render broken links.

# Requirement 4 — Blog Search

Add client-side search to:

```text
/blog
```

Search should work on existing loaded blog metadata.

Do not introduce:

* database
* external search service
* backend search API

Search fields should include at least:

```text
title
description
category
tags
```

Searching full Markdown body text is optional.

Prefer metadata search for Version 5.3 unless full-content search can be implemented cleanly without significantly increasing complexity.

Example:


For example:

```text

AND
Tag matches
```

# Requirement 8 — URL Search Parameters

Where reasonably simple, synchronize Blog filtering state with URL query parameters.

Example:

```text
/blog?category=computer-vision
```

or:

```text
/blog?tag=cs231n
```

or:

```text
/blog?q=git
```

This allows filtered views to be shareable.

Prefer readable query parameters.

Do not introduce a complex routing architecture solely for this feature.

If combining every filter into URL state significantly complicates the implementation, prioritize:

```text
q
category
tag
```

only.

---

# Requirement 9 — Reading Progress Indicator

Add a subtle article reading-progress indicator.

It should represent approximately:

```text
0% → 100%
```

as the reader scrolls through an article.

A simple thin progress bar is sufficient.

Do not make it visually dominant.

---

## Behavior

At the top of the article:

```text
0%
```

Near the bottom:

```text
100%
```

The visual bar should update smoothly as the reader scrolls.

---

## Architecture

Only the reading-progress behavior should require client-side code.

Do not convert the entire article rendering system into a Client Component.

Prefer:

```text
Server Article Page
       │
       ├── Markdown Content
       │
       └── Small Client Progress Component
```

Keep client-side JavaScript isolated.

---

Example:

```text

```

Use an efficient browser API such as:


If implementing active-section tracking requires excessive complexity, prioritize:

1. Functional TOC links
2. Stable heading IDs
3. Responsive TOC layout

before active highlighting.

# Performance Requirements

Avoid unnecessary large client-side bundles.

Prefer:

```text
Server Components
```

for:

* Markdown reading
* article rendering
* blog data access

Use Client Components only where browser interaction requires them:

```text
Search / filtering UI
Reading progress
Optional active TOC tracking
```

Do not convert the entire Blog system to client-side rendering.

---

# Dependency Policy

Reuse existing dependencies whenever possible.

Only add dependencies if they meaningfully simplify:

* heading slug generation
* Markdown TOC generation
* existing Markdown processing

Do not install:

* complete blog frameworks
* UI frameworks
* search services
* large state management libraries

Simple React state is enough for filtering.

---

# Do NOT Implement

Do not add:

* Database
* CMS
* Authentication
* User accounts
* Comments
* Likes
* Online Markdown editor
* Admin panel
* External search service
* Analytics dashboard
* Newsletter system

These are unnecessary for the current personal technical website.
