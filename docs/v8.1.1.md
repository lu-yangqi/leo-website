# V8.1.1 --- Leo Signature Integration

## Task

Integrate the finalized Leo handwritten signature asset into the
existing V8.1 cinematic Hero sequence.

The goal is to replace the temporary signature placeholder with the real
SVG signature while preserving the existing Hero animation architecture.

------------------------------------------------------------------------

## Main Goal

Complete the Hero identity transition:

``` text
Portrait
    ↓
Center Focus
    ↓
Leo Signature Reveal
    ↓
Homepage Content
```

The final experience should make the signature feel like a natural
continuation of the portrait transition.

------------------------------------------------------------------------

## Requirements

## Signature Asset Integration

Replace:

``` text
SignaturePlaceholder
```

with:

``` text
Leo Signature SVG
```

Requirements:

-   Use the provided `leo-signature.svg`
-   Preserve the original handwritten shape
-   Do not redesign or regenerate the signature
-   Keep the SVG isolated as a replaceable asset

Suggested location:

``` text
public/
└── signatures/
    └── leo-signature.svg
```

------------------------------------------------------------------------

## Signature Reveal Animation

The signature should appear progressively instead of instantly fading
in.

Preferred behavior:

``` text
0%
Invisible

↓

30%
Beginning of signature appears

↓

70%
Main Leo shape visible

↓

100%
Complete signature revealed
```

Possible implementations:

-   SVG mask reveal
-   stroke-based reveal if compatible
-   clip-path animation

The final implementation should prioritize visual quality and
maintainability.

------------------------------------------------------------------------

## Hero Timeline

Keep the existing V8.1 cinematic sequence.

Target:

``` text
01 Portrait Introduction

Large visual identity

↓

02 Center Lock

Portrait scales and moves into position

↓

03 Signature Reveal

Leo signature appears

↓

04 Transition

Homepage content becomes active
```

Do not rewrite the existing Hero controller.

------------------------------------------------------------------------

## Technical Constraints

Preserve:

-   Existing routes
-   Existing SEO system
-   Existing bilingual architecture
-   Existing Markdown blog system
-   Existing profile and project data

Avoid:

-   Architecture rewrite
-   New heavy animation dependencies
-   Replacing the current Hero motion system

------------------------------------------------------------------------

## Performance Requirements

The implementation should:

-   Maintain smooth scrolling
-   Avoid React state updates on every scroll frame
-   Respect `prefers-reduced-motion`
-   Keep static fallback behavior
-   Avoid layout shifts
